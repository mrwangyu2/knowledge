# sub-agent

> **一句话概括：** 把复杂任务拆给多个"专属小助手"并行处理，每个子代理在独立的工作空间里专注完成一件事，最后把结果汇总给你。

## 这是什么？

Sub-agent（子代理）是 Claude Code 内置的"分身术"。你可以让 AI 派生出多个独立的 AI 助手，每个都有自己的上下文、工具权限、专属指令，互不干扰地并行工作。

## 核心好处

| 优势 | 说明 |
|------|------|
| 🧊 **上下文隔离** | 子代理干完活就消失，中间产生的垃圾不会污染主会话 |
| ⚡ **并行执行** | 多个代理同时干活，实际等待时间大大缩短 |
| 🎯 **专事专办** | 每个子代理可以配不同的模型和指令，各司其职 |
| 🔒 **权限可控** | 可以限制每个子代理能用的工具，审查员不能改代码 |

## 内置子代理

| 名称 | 模型 | 用途 |
|------|------|------|
| **General-purpose** | 继承主模型 | 复杂多步骤任务 |
| **Plan** | 继承主模型 | 架构设计、方案规划（只读工具） |
| **Explore** | Haiku | 快速代码搜索（又快又便宜） |
| **Bash** | 继承主模型 | 在独立上下文里跑命令 |

## 自定义子代理

在 `.claude/agents/` 下创建 Markdown 文件：

```markdown
---
name: api-test-writer
description: 为新增或变更的 API 端点编写测试用例
tools: Read, Grep, Write, Bash
model: sonnet
---

1. 读取 OpenAPI 规范和端点实现
2. 编写覆盖成功场景、验证错误、权限校验的测试
3. 断言状态码，用 schema 校验响应体
4. 运行测试套件，报告通过/失败及原因
```

## 什么时候用？

| ✅ 适合用子代理 | ❌ 不适合 |
|---------------|----------|
| Code Review | 改一个变量名 |
| 写测试用例 | 修一行 bug |
| 安全审计 | 小范围重构 |
| 并行搜索多个目录 | 简单文件操作 |
| 独立任务（不依赖上下文） | 需要全盘理解的任务 |

## 最佳实践

- **一个子代理只做一件事** — 专一才能做好
- **描述要清楚** — `description` 字段写得越准确，AI 越会自动派活
- **最小权限原则** — Review 子代理不给写权限，防止误改
- **返回结构化结果** — 让子代理按固定格式汇报（通过/失败、问题列表）
- **别套娃** — 子代理里再分子代理，层次一深又贵又乱
