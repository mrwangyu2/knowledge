## 1. Introduction and Scope

### 原文

The present-day Internet has seen ubiquitous deployment of Network Address Translators (NATs). There are a variety of NAT devices and a variety of network topologies utilizing NAT devices in deployments. The asymmetric addressing and connectivity regimes established by these NAT devices have created unique problems for peer-to-peer (P2P) applications and protocols, such as teleconferencing and multiplayer online gaming. These issues are likely to persist even into the IPv6 world. During the transition to IPv6, some form of NAT may be required to enable IPv4-only nodes to communicate with IPv6-only nodes [NAT-PT], although the appropriate protocols and guidelines for this use of NAT are still unresolved [NAT-PT-HIST]. Even a future "pure IPv6 world" may still include firewalls, which employ similar filtering behavior of NATs but without the address translation [V6-CPE-SEC]. The filtering behavior interferes with the functioning of P2P applications. For this reason, IPv6 applications that use the techniques described in this document for NAT traversal may also work with some firewalls that have filtering behavior similar to NATs.

### 中文

当今互联网已经广泛部署了网络地址转换器（NAT）。NAT 设备种类繁多，部署中的网络拓扑结构也多种多样。这些 NAT 设备建立的非对称寻址和连接模式给点对点（P2P）应用和协议（如电话会议和多人在线游戏）带来了独特的问题。这些问题即使在 IPv6 时代也可能继续存在。在向 IPv6 过渡期间，可能需要某种形式的 NAT 来使纯 IPv4 节点与纯 IPv6 节点通信 [NAT-PT]，尽管这种 NAT 用途的适当协议和指南仍未解决 [NAT-PT-HIST]。即使未来的"纯 IPv6 世界"可能仍然包括防火墙，它们采用与 NAT 相似的过滤行为，但不进行地址转换 [V6-CPE-SEC]。这种过滤行为会干扰 P2P 应用的功能。因此，使用本文档描述的 NAT 穿透技术的 IPv6 应用也可能适用于某些具有类似 NAT 过滤行为的防火墙。

---

### 原文

Currently deployed NAT devices are designed primarily around the client/server paradigm, in which relatively anonymous client machines inside a private network initiate connections to public servers with stable IP addresses and DNS names. NAT devices encountered en route provide dynamic address assignment for the client machines. The illusion of anonymity (private IP addresses) and inaccessibility of the internal hosts behind a NAT device is not a problem for applications such as Web browsers, which only need to initiate outgoing connections. This illusion of anonymity and inaccessibility is sometimes perceived as a privacy benefit. As noted in Section 2.2 of [RFC4941], this perceived privacy may be illusory in a majority of cases utilizing Small-Office-Home-Office (SOHO) NATs.

### 中文

目前部署的 NAT 设备主要围绕客户端/服务器模式设计，其中私有网络内相对匿名的客户端机器发起与具有稳定 IP 地址和 DNS 名称的公共服务器的连接。沿途遇到的 NAT 设备为客户端机器提供动态地址分配。匿名性（私有 IP 地址）的假象和 NAT 设备后面内部主机的不可访问性对于 Web 浏览器等只需要发起传出连接的应用来说不是问题。这种匿名性和不可访问性的假象有时被视为一种隐私优势。正如 [RFC4941] 第 2.2 节所述，在大多数使用小型办公室家庭办公室（SOHO）NAT 的情况下，这种 perceived 隐私可能是虚幻的。

---

### 原文

In the peer-to-peer paradigm, Internet hosts that would normally be considered "clients" not only initiate sessions to peer nodes, but also accept sessions initiated by peer nodes. The initiator and the responder might lie behind different NAT devices with neither endpoint having a permanent IP address or other form of public network presence. A common online gaming architecture, for example, involves all participating application hosts contacting a publicly addressable rendezvous server for registering themselves and discovering peer hosts. Subsequent to the communication with the rendezvous server, the hosts establish direct connections with each other for fast and efficient propagation of updates during game play. Similarly, a file sharing application might contact a well-known rendezvous server for resource discovery or searching, but establish direct connections with peer hosts for data transfer. NAT devices create problems for peer-to-peer connections because hosts behind a NAT device normally have no permanently visible public ports on the Internet to which incoming TCP or UDP connections from other peers can be directed. RFC 3235 [NAT-APPL] briefly addresses this issue.

### 中文

在点对点模式中，通常被视为"客户端"的互联网主机不仅向对等节点发起会话，还接受对等节点发起的会话。发起方和响应方可能位于不同的 NAT 设备后面，双方都没有永久 IP 地址或其他形式的公共网络存在。例如，常见的在线游戏架构涉及所有参与应用主机联系一个公开可寻址的 rendezvous 服务器来注册自己和发现对等主机。在与 rendezvous 服务器通信之后，主机之间建立直接连接，以便在游戏过程中快速高效地传播更新。类似地，文件共享应用可能联系一个知名的 rendezvous 服务器进行资源发现或搜索，但建立与对等主机的直接连接进行数据传输。NAT 设备给点对点连接带来了问题，因为 NAT 设备后面的主机通常没有永久可见的公共端口，其他对等体的传入 TCP 或 UDP 连接无法定向到这些端口。RFC 3235 [NAT-APPL] 简要讨论了这个问题。

---

These techniques, if available, are a complement to the techniques described in the document. [UNSAF] is in scope.

### 中文

涉及应用和 NAT 设备之间显式信令的 NAT 穿透策略，即 [NAT-PMP]、[NSIS-NSLP]、[SOCKS]、[RSIP]、[MIDCOM] 和 [UPNP] 不在本文档范围内。如果这些技术可用，它们是对本文档描述技术的补充。[UNSAF] 在范围内。

---

### 原文

In this document, we summarize the currently known methods by which applications work around the presence of NAT devices, without directly altering the NAT devices. The techniques described predate BEHAVE documents ([BEH-UDP], [BEH-TCP], and [BEH-ICMP]). The scope of the document is restricted to describing currently known techniques used to establish 2-way communication between endpoints of an application. Discussion of timeouts, RST processing, keepalives, and so forth that concern a running session are outside the scope of this document. The scope is also restricted to describing techniques for TCP- and UDP-based applications. It is not the objective of this document to provide solutions to NAT traversal problems for applications in general [BEH-APP] or to a specific class of applications [ICE].

### 中文

在本文档中，我们总结目前已知的方法，应用通过这些方法绕过 NAT 设备的存在，而不直接改变 NAT 设备。描述的技术早于 BEHAVE 文档（[BEH-UDP]、[BEH-TCP] 和 [BEH-ICMP]）。本文档的范围仅限于描述目前已知用于在应用端点之间建立双向通信的技术。关于超时、RST 处理、保活等运行会话的讨论不在本文档范围内。范围也仅限于描述基于 TCP 和 UDP 应用的技术。本文档的目的不是为通用应用 [BEH-APP] 或特定类别的应用 [ICE] 提供 NAT 穿透问题的解决方案。

## 2. Terminology and Conventions Used

### 原文

In this document, the IP addresses 192.0.2.1, 192.0.2.128, and 192.0.2.254 are used as example public IP addresses [RFC3330]. Although these addresses are all from the same /24 network, this is a limitation of the example addresses available in [RFC3330]. In practice, these addresses would be on different networks. As for the notation for ports usage, all clients use ports in the range of 1-2000 and servers use ports in the range of 20000-21000. NAT devices use ports 30000 and above for endpoint mapping.

### 中文

在本文档中，IP 地址 192.0.2.1、192.0.2.128 和 192.0.2.254 用作示例公共 IP 地址 [RFC3330]。尽管这些地址都来自同一个 /24 网络，但这是 [RFC3330] 中可用示例地址的限制。实际上，这些地址会在不同的网络上。至于端口使用表示法，所有客户端使用 1-2000 范围内的端口，服务器使用 20000-21000 范围内的端口。NAT 设备使用 30000 及以上的端口进行端点映射。

---

### 原文

Readers are urged to refer to [NAT-TERM] for information on NAT taxonomy and terminology. Unless prefixed with a NAT type or explicitly stated otherwise, the term NAT, used throughout this document, refers to Traditional NAT [NAT-TRAD]. Traditional NAT has two variations, namely, Basic NAT and Network Address Port Translator (NAPT). Of these, NAPT is by far the most commonly deployed NAT device. NAPT allows multiple private hosts to share a single public IP address simultaneously.

### 中文

强烈建议读者参阅 [NAT-TERM] 获取 NAT 分类和术语的信息。除非带有 NAT 类型前缀或明确说明，否则本文档中使用的 NAT 术语指的是传统 NAT [NAT-TRAD]。传统 NAT 有两种变体，即基本 NAT 和网络地址端口转换器（NAPT）。其中，NAPT 是迄今为止部署最广泛的 NAT 设备。NAPT 允许多个私有主机同时共享一个公共 IP 地址。

---

### 原文

An issue of relevance to P2P applications is how the NAT behaves when an internal host initiates multiple simultaneous sessions from a single endpoint (private IP, private port) to multiple distinct endpoints on the external network.

### 中文

与 P2P 应用相关的一个问题是：当内部主机从单个端点（私有 IP、私有端口）向外部网络的多个不同端点发起多个并发会话时，NAT 如何表现。

Unfortunately, this terminology has been the source of much confusion. For this reason, this document adapts terminology from [BEH-UDP] to distinguish between NAT implementations.

[STUN] 使用"全锥型"、"限制锥型"、"端口限制锥型"和"对称型"等术语进一步对 NAT 实现进行分类。不幸的是，这种术语一直是混淆的来源。因此，本文档采用 [BEH-UDP] 的术语来区分 NAT 实现。

Listed below are terms used throughout this document.

### 中文

以下是本文档中使用的术语列表。

---

### 原文

#### 2.1. Endpoint

An endpoint is a session-specific tuple on an end host. An endpoint may be represented differently for each IP protocol. For example, a UDP or TCP session endpoint is represented as a tuple of (IP address, UDP/TCP port).

### 中文

#### 2.1. 端点

端点是终端主机上特定会话的元组。端点对于不同的 IP 协议可能有不同的表示。例如，UDP 或 TCP 会话端点表示为（IP 地址、UDP/TCP 端口）的元组。

---

### 原文

#### 2.2. Endpoint Mapping

When a host in a private realm initiates an outgoing session to a host in the public realm through a NAT device, the NAT device assigns a public endpoint to translate the private endpoint so that subsequent response packets from the external host can be received by the NAT, translated, and forwarded to the private endpoint. The assignment by the NAT device to translate a private endpoint to a public endpoint and vice versa is called Endpoint Mapping. NAT uses Endpoint Mapping to perform translation for the duration of the session.

### 中文

#### 2.2. 端点映射

当私有域中的主机通过 NAT 设备向公共域中的主机发起传出会话时，NAT 设备分配一个公共端点来转换私有端点，以便 NAT 能够接收来自外部主机的后续响应数据包，进行转换，并转发到私有端点。NAT 设备将私有端点转换为公共端点（反之亦然）的这种分配称为端点映射。NAT 在会话期间使用端点映射执行转换。

---

### 原文

#### 2.3. Endpoint-Independent Mapping

"Endpoint-Independent Mapping" is defined in [BEH-UDP] as follows:

The NAT reuses the port mapping for subsequent packets sent from the same internal IP address and port (X:x) to any external IP address and port.

### 中文

#### 2.3. 端点无关映射

"端点无关映射"在 [BEH-UDP] 中定义如下：

NAT 为从同一内部 IP 地址和端口（X:x）发送到任何外部 IP 地址和端口的后续数据包重用端口映射。

---

### 原文

#### 2.4. Endpoint-Dependent Mapping

"Endpoint-Dependent Mapping" refers to the combination of "Address-Dependent Mapping" and "Address and Port-Dependent Mapping" as defined in [BEH-UDP]:

Address-Dependent Mapping

The NAT reuses the port mapping for subsequent packets sent from the same internal IP address and port (X:x) to the same external IP address, regardless of the external port.

Address and Port-Dependent Mapping

The NAT reuses the port mapping for subsequent packets sent from the same internal IP address and port (X:x) to the same external IP address and port while the mapping is still active.

### 中文

#### 2.4. 端点相关映射

"端点相关映射"指的是 [BEH-UDP] 中定义的"地址相关映射"和"地址和端口相关映射"的组合：

地址相关映射

NAT 为从同一内部 IP 地址和端口（X:x）发送到同一外部 IP 地址（无论外部端口如何）的后续数据包重用端口映射。

地址和端口相关映射

只要映射处于活跃状态，NAT 为从同一内部 IP 地址和端口（X:x）发送到同一外部 IP 地址和端口的后续数据包重用端口映射。

---

### 原文

#### 2.5. Endpoint-Independent Filtering

"Endpoint-Independent Filtering" is defined in [BEH-UDP] as follows:

The NAT filters out only packets not destined to the internal address and port X:x, regardless of the external IP address and port source (Z:z). The NAT forwards any packets destined to X:x. In other words, sending packets from the internal side of the NAT to any external IP address is sufficient to allow any packets back to the internal endpoint.

### 中文

#### 2.5. 端点无关过滤

"端点无关过滤"在 [BEH-UDP] 中定义如下：

NAT 仅过滤掉不以内部地址和端口 X:x 为目的地的数据包，无论外部 IP 地址和端口源（Z:z）如何。NAT 转发所有以 X:x 为目的地的数据包。换句话说，从 NAT 内部侧向任何外部 IP 地址发送数据包足以允许任何数据包返回到内部端点。

---

### 原文

A NAT device employing the combination of "Endpoint-Independent Mapping" and "Endpoint-Independent Filtering" will accept incoming traffic to a mapped public port from ANY external endpoint on the public network.

### 中文

采用"端点无关映射"和"端点无关过滤"组合的 NAT 设备将从公共网络上任何外部端点接受到映射公共端口的传入流量。

---

### 原文

#### 2.6. Endpoint-Dependent Filtering

"Endpoint-Dependent Filtering" refers to the combination of "Address-Dependent Filtering" and "Address and Port-Dependent Filtering" as defined in [BEH-UDP].

Address-Dependent Filtering

The NAT filters out packets not destined to the internal address X:x. Additionally, the NAT will filter out packets from Y:y destined for the internal endpoint X:x if X:x has not sent packets to Y:any previously (independently of the port used by Y). In other words, for receiving packets from a specific external endpoint, it is necessary for the internal endpoint to send packets first to that specific external endpoint's IP address.

Address and Port-Dependent Filtering

The NAT filters out packets not destined for the internal address X:x. Additionally, the NAT will filter out packets from Y:y destined for the internal endpoint X:x if X:x has not sent packets to Y:y previously. In other words, for receiving packets from a specific external endpoint, it is necessary for the internal endpoint to send packets first to that external endpoint's IP address and port.

### 中文

#### 2.6. 端点相关过滤

"端点相关过滤"指的是 [BEH-UDP] 中定义的"地址相关过滤"和"地址和端口相关过滤"的组合。

地址相关过滤

NAT 过滤掉不以内部地址 X:x 为目的地的数据包。此外，如果 X:x 之前没有向 Y:any 发送过数据包（独立于 Y 使用的端口），NAT 将过滤掉从 Y:y 发送到内部端点 X:x 的数据包。换句话说，为了从特定外部端点接收数据包，内部端点必须首先向该特定外部端点的 IP 地址发送数据包。

地址和端口相关过滤

NAT 过滤掉不以内部地址 X:x 为目的地的数据包。此外，如果 X:x 之前没有向 Y:y 发送过数据包，NAT 将过滤掉从 Y:y 发送到内部端点 X:x 的数据包。换句话说，为了从特定外部端点接收数据包，内部端点必须首先向该外部端点的 IP 地址和端口发送数据包。

---

### 原文

A NAT device employing "Endpoint-Dependent Filtering" will accept incoming traffic to a mapped public port from only a restricted set of external endpoints on the public network.

### 中文

采用"端点相关过滤"的 NAT 设备将仅接受来自公共网络上受限的外部端点集的传入流量到映射的公共端口。

---

### 原文

#### 2.7. P2P Application

A P2P application is an application that uses the same endpoint to initiate outgoing sessions to peering hosts as well as accept incoming sessions from peering hosts. A P2P application may use multiple endpoints for peer-to-peer communication.

### 中文

#### 2.7. P2P 应用

P2P 应用是使用同一端点向对等主机发起传出会话并接受来自对等主机的传入会话的应用。P2P 应用可能使用多个端点进行点对点通信。

---

### 原文

#### 2.8. NAT-Friendly P2P Application

A NAT-friendly P2P application is a P2P application that is designed to work effectively even as peering nodes are located in distinct IP address realms, connected by one or more NATs.

One common way P2P applications establish peering sessions and remain NAT-friendly is by using a publicly addressable rendezvous server for registration and peer discovery purposes.

### 中文

#### 2.8. NAT 友好的 P2P 应用

NAT 友好的 P2P 应用是一种 P2P 应用，即使对等节点位于由一个或多个 NAT 连接的 不同 IP 地址域中，也能有效工作。

P2P 应用建立对等会话并保持 NAT 友好的一种常见方式是使用公开可寻址的 rendezvous 服务器进行注册和对等发现。

---

### 原文

#### 2.9. Endpoint-Independent Mapping NAT (EIM-NAT)

An Endpoint-Independent Mapping NAT (EIM-NAT, for short) is a NAT device employing Endpoint-Independent Mapping. An EIM-NAT can have any type of filtering behavior. BEHAVE-compliant NAT devices are good examples of EIM-NAT devices. A NAT device employing Address-Dependent Mapping is an example of a NAT device that is not EIM-NAT.

### 中文

#### 2.9. 端点无关映射 NAT (EIM-NAT)

端点无关映射 NAT（简称 EIM-NAT）是采用端点无关映射的 NAT 设备。EIM-NAT 可以具有任何类型的过滤行为。符合 BEHAVE 标准的 NAT 设备是 EIM-NAT 设备的好例子。采用地址相关映射的 NAT 设备是非 EIM-NAT 的例子。

---

### 原文

#### 2.10. Hairpinning

Hairpinning is defined in [BEH-UDP] as follows:

If two hosts (called X1 and X2) are behind the same NAT and exchanging traffic, the NAT may allocate an address on the outside of the NAT for X2, called X2':x2'. If X1 sends traffic to X2':x2', it goes to the NAT, which must relay the traffic from X1 to X2. This is referred to as hairpinning.

Not all currently deployed NATs support hairpinning.

### 中文

#### 2.10. 发夹式（Hairpinning）

[BEH-UDP] 将 hairpinning 定义如下：

如果两个主机（称为 X1 和 X2）在同一 NAT 后面并交换流量，NAT 可能为 X2 在 NAT 外部分配一个地址，称为 X2':x2'。如果 X1 向 X2':x2' 发送流量，它会到达 NAT，NAT 必须将流量从 X1 中继到 X2。这称为 hairpinning。

并非所有当前部署的 NAT 都支持 hairpinning。

## 3. Techniques Used by P2P Applications to Traverse NATs

### 原文

This section reviews in detail the currently known techniques for implementing peer-to-peer communication over existing NAT devices, from the perspective of the application or protocol designer.

### 中文

本节详细回顾了从应用或协议设计者的角度，在现有 NAT 设备上实现点对点通信的已知技术。

---

### 原文

#### 3.1. Relaying

The most reliable, but least efficient, method of implementing peer-to-peer communication in the presence of a NAT device is to make the peer-to-peer communication look to the network like client/server communication through relaying. Consider the scenario in figure 1. Two client hosts, A and B, have each initiated TCP or UDP connections to a well-known rendezvous server S. The Rendezvous Server S has a publicly addressable IP address and is used for the purposes of registration, discovery, and relay. Hosts behind NAT register with the server. Peer hosts can discover hosts behind NATs and relay all end-to-end messages using the server. The clients reside on separate private networks, and their respective NAT devices prevent either client from directly initiating a connection to the other.

### 中文

#### 3.1. 中继（Relaying）

在 NAT 设备存在的情况下，实现点对点通信最可靠但效率最低的方法是通过中继使点对点通信在网络上看起来像客户端/服务器通信。考虑图 1 中的场景。两个客户端主机 A 和 B 各自向知名的 rendezvous 服务器 S 发起 TCP 或 UDP 连接。Rendezvous 服务器 S 具有公开可寻址的 IP 地址，用于注册、发现和中继。NAT 后面的主机在服务器上注册。对等主机可以发现 NAT 后面的主机，并使用服务器中继所有端到端消息。客户端位于独立的私有网络上，它们各自的 NAT 设备阻止任一客户端直接发起与另一方的连接。

---

### 原文

Instead of attempting a direct connection, the two clients can simply use the server S to relay messages between them. For example, to send a message to client B, client A simply sends the message to server S along its already established client/server connection, and server S then sends the message on to client B using its existing client/server connection with B.

### 中文

两个客户端不尝试直接连接，而是可以简单地使用服务器 S 在它们之间中继消息。例如，为了向客户端 B 发送消息，客户端 A 只需沿其已建立的客户端/服务器连接将消息发送到服务器 S，然后服务器 S 使用其与 B 现有的客户端/服务器连接将消息发送给客户端 B。

---

### 原文

This method has the advantage that it will always work as long as both clients have connectivity to the server. The enroute NAT device is not required to be EIM-NAT. The obvious disadvantages of relaying are that it consumes the server's processing power and network bandwidth, and communication latency between the peering clients is likely to be increased even if the server has sufficient I/O bandwidth and is located correctly topology-wise. The TURN protocol [TURN] defines a method of implementing application agnostic, session-oriented, packet relay in a relatively secure fashion.

### 中文

这种方法的优势在于，只要两个客户端都能连接到服务器，它就始终有效。沿途的 NAT 设备不需要是 EIM-NAT。中继的明显缺点是它消耗服务器的 processing power 和网络带宽，即使服务器具有足够的 I/O 带宽且拓扑位置正确，对等客户端之间的通信延迟也可能会增加。TURN 协议 [TURN] 定义了一种以相对安全的方式实现应用无关的、面向会话的数据包中继的方法。

### 原文

#### 3.2. Connection Reversal

The following connection reversal technique for a direct communication works only when one of the peers is behind a NAT device and the other is not. For example, consider the scenario in figure 2. Client A is behind a NAT, but client B has a publicly addressable IP address. Rendezvous Server S has a publicly addressable IP address and is used for the purposes of registration and discovery. Hosts behind a NAT register their endpoints with the server. Peer hosts discover endpoints of hosts behind a NAT using the server.

### 中文

#### 3.2. 连接反转（Connection Reversal）

以下直接通信的连接反转技术仅在其中一个对等体位于 NAT 设备后面而另一个不是时才有效。例如，考虑图 2 中的场景。客户端 A 位于 NAT 后面，但客户端 B 具有公开可寻址的 IP 地址。Rendezvous 服务器 S 具有公开可寻址的 IP 地址，用于注册和发现。NAT 后面主机在服务器上注册其端点。对等主机使用服务器发现 NAT 后面主机的端点。

---

### 原文

Client A has private IP address 10.0.0.1, and the application is using TCP port 1234. This client has established a connection with server S at public IP address 192.0.2.128 and port 20001. NAT A has assigned TCP port 62000, at its own public IP address 192.0.2.1, to serve as the temporary public endpoint address for A's session with S; therefore, server S believes that client A is at IP address 192.0.2.1 using port 62000. Client B, however, has its own permanent IP address, 192.0.2.254, and the application on B is accepting TCP connections at port 1234.

### 中文

客户端 A 具有私有 IP 地址 10.0.0.1，应用使用 TCP 端口 1234。此客户端已与服务器 S 在公共 IP 地址 192.0.2.128 和端口 20001 上建立连接。NAT A 分配了 TCP 端口 62000（在其自己的公共 IP 地址 192.0.2.1 上）作为 A 与 S 会话的临时公共端点地址；因此，服务器 S 认为客户端 A 位于 IP 地址 192.0.2.1 使用端口 62000。然而，客户端 B 有自己的永久 IP 地址 192.0.2.254，B 上的应用在端口 1234 接受 TCP 连接。

### 原文

Now suppose client B wishes to establish a direct communication session with client A. B might first attempt to contact client A either at the address client A believes itself to have, namely, 10.0.0.1:1234, or at the address of A as observed by server S, namely, 192.0.2.1:62000. In either case, the connection will fail. In the first case, traffic directed to IP address 10.0.0.1 will simply be dropped by the network because 10.0.0.1 is not a publicly routable IP address. In the second case, the TCP SYN request from B will arrive at NAT A directed to port 62000, but NAT A will reject the connection request because only outgoing connections are allowed.

### 中文

现在假设客户端 B 希望与客户端 A 建立直接通信会话。B 可能首先尝试联系客户端 A，可以是 A 认为自己的地址，即 10.0.0.1:1234，或者是服务器 S 观察到的 A 的地址，即 192.0.2.1:62000。在任何一种情况下，连接都将失败。在第一种情况下，发送到 IP 地址 10.0.0.1 的流量将被网络直接丢弃，因为 10.0.0.1 不是公开可路由的 IP 地址。在第二种情况下，来自 B 的 TCP SYN 请求将到达 NAT A 定向到端口 62000，但 NAT A 将拒绝连接请求，因为只允许传出连接。

### 原文

After attempting and failing to establish a direct connection to A, client B can use server S to relay a request to client A to initiate a "reversed" connection to client B. Client A, upon receiving this relayed request through S, opens a TCP connection to client B at B's public IP address and port number. NAT A allows the connection to proceed because it is originating inside the firewall, and client B can receive the connection because it is not behind a NAT device.

### 中文

在尝试并失败建立到 A 的直接连接后，客户端 B 可以使用服务器 S 中继请求到客户端 A，发起到客户端 B 的"反向"连接。客户端 A 收到通过 S 中继的此请求后，向客户端 B 的公共 IP 地址和端口号打开 TCP 连接。NAT A 允许连接继续进行，因为它源自防火墙内部，而客户端 B 可以接收连接，因为它不在 NAT 设备后面。

### 原文

A variety of current peer-to-peer applications implement this technique. Its main limitation, of course, is that it only works so long as only one of the communicating peers is behind a NAT device. If the NAT device is EIM-NAT, the public client can contact external server S to determine the specific public endpoint from which to expect Client-A-originated connection and allow connections from just those endpoints. If the NAT device is EIM-NAT, the public client can contact the external server S to determine the specific public endpoint from which to expect connections originated by client A, and allow connections from just that endpoint. If the NAT device is not EIM-NAT, the public client cannot know the specific public endpoint from which to expect connections originated by client A. In the increasingly common case where both peers can be behind NATs, the Connection Reversal method fails. Connection Reversal is not a general solution to the peer-to-peer connection problem. If neither a "forward" nor a "reverse" connection can be established, applications often fall back to another mechanism such as relaying.

### 中文

多种当前的点对点应用实现了这种技术。当然，它的主要限制是它仅在通信对等体中只有一个位于 NAT 设备后面时才有效。如果 NAT 设备是 EIM-NAT，公共客户端可以联系外部服务器 S 以确定特定公共端点，预期来自客户端 A 的连接将从该端点发起，并仅允许来自这些端点的连接。如果 NAT 设备是 EIM-NAT，公共客户端可以联系外部服务器 S 以确定预期来自客户端 A 连接发起的特定公共端点，并仅允许来自该端点的连接。如果 NAT 设备不是 EIM-NAT，公共客户端无法知道预期来自客户端 A 连接发起的特定公共端点。在双方对等体都可能位于 NAT 后面的日益常见的情况下，连接反转方法失败。连接反转不是点对点连接问题的通用解决方案。如果既无法建立"正向"也无法建立"反向"连接，应用通常会回退到另一种机制，如中继。

### 原文

#### 3.3. UDP Hole Punching

UDP hole punching relies on the properties of EIM-NATs to allow appropriately designed peer-to-peer applications to "punch holes" through the NAT device(s) enroute and establish direct connectivity with each other, even when both communicating hosts lie behind NATs.

### 中文

#### 3.3. UDP 打洞（UDP Hole Punching）

UDP 打洞依赖于 EIM-NAT 的属性，允许适当设计的点对点应用通过沿途的 NAT 设备"打洞"，即使两个通信主机都位于 NAT 后面，也能建立彼此之间的直接连接。

---

### 原文

The UDP hole punching technique works as follows. Suppose two hosts, A and B, behind EIM-NATs wish to communicate. Both A and B are symmetric -- they are simultaneously clients and servers. Assume they both initially know each other's presence through the rendezvous server S. The rendezvous server S has a public IP address and is used for the registration and discovery of peers.

### 中文

UDP 打洞技术工作原理如下。假设位于 EIM-NAT 后面的两个主机 A 和 B 希望通信。A 和 B 都是对称的——它们同时是客户端和服务器。假设它们最初都通过 rendezvous 服务器 S 知道彼此的存在。Rendezvous 服务器 S 具有公共 IP 地址，用于对等的注册和发现。

---

### 原文

The process for establishing a peer-to-peer communication is as follows. A and B each send a UDP probe to S. The NAT boxes at A and B create "holes" for outbound UDP packets. The NAT boxes note the UDP port each internal host is using, and also note the UDP port each host is trying to communicate on the external side of the NAT. A and B exchange the NAT holes' addresses via S.

### 中文

建立点对点通信的过程如下。A 和 B 各自向 S 发送 UDP probe。A 和 B 的 NAT 盒子为出站 UDP 数据包创建"洞"。NAT 盒子记录每个内部主机使用的 UDP 端口，还记录每个主机尝试在 NAT 外部通信的 UDP 端口。A 和 B 通过 S 交换 NAT 洞的地址。

---

### 原文

##### 3.3.1. Peers behind Different NATs

Consider the topology in figure 3. The two hosts, A and B, are behind different NATs. This is the most common scenario for peers across the open Internet.

### 中文

##### 3.3.1. 位于不同 NAT 后面的对等体

考虑图 3 中的拓扑。两个主机 A 和 B 位于不同的 NAT 后面。这是对等体跨开放互联网最常见的场景。

### 原文

A and B each initiate a UDP session with S. The NATs assign each of these sessions a public endpoint (public IP:port). A's endpoint registered with S is 192.0.2.1:62000, and B's endpoint is 192.0.2.128:31000. A's and B's respective endpoints are now registered with S. The rendezvous server S can return the peer's registered endpoint to the other peer. The rendezvous server S sends A's endpoint to B, and sends B's endpoint to A.

### 中文

A 和 B 各自与 S 发起 UDP 会话。NAT 为每个会话分配一个公共端点（公共 IP:端口）。A 注册到 S 的端点是 192.0.2.1:62000，B 的端点是 192.0.2.128:31000。A 和 B 各自的端点现已注册到 S。Rendezvous 服务器 S 可以将对等的注册端点返回给另一个对等体。Rendezvous 服务器 S 将 A 的端点发送给 B，并将 B 的端点发送给 A。

---

### 原文

Now A sends a UDP datagram to B's public endpoint (192.0.2.128:31000), and B sends a UDP datagram to A's public endpoint (192.0.2.1:62000) at roughly the same time. When A's first UDP datagram arrives at NAT A, the NAT may or may not have an existing mapping for destination 192.0.2.128:31000. If there's no mapping, then NAT A creates a new mapping for this datagram. Similarly for NAT B. After this exchange of datagrams, both NATs have forward mappings for each other's addresses, and each NAT's internal host is able to receive packets from the other.

### 中文

现在 A 向 B 的公共端点（192.0.2.128:31000）发送 UDP 数据报，B 同时向 A 的公共端点（192.0.2.1:62000）发送 UDP 数据报。当 A 的第一个 UDP 数据报到达 NAT A 时，NAT 可能或可能没有到目的地 192.0.2.128:31000 的现有映射。如果没有映射，NAT A 为此数据报创建一个新映射。NAT B 也一样。在这种数据报交换之后，两个 NAT 都有彼此地址的前向映射，每个 NAT 的内部主机能够从对方接收数据包。

---

### 原文

Because NAT behavior is not always predictable, the timing of theUDP datagrams from both ends is critical. The rendezvous server S instructs A and B to send packets "at the same time" to each other's addresses. To achieve this, S may instruct A and B to send packets to each other after some initial delay. Also, it is possible that only one of the NATs will create a valid mapping while the other receives an unexpected response. In such cases, applications may need to retry the process with different ports.

### 中文

由于 NAT 行为并不总是可预测的，来自两端 UDP 数据报的时序至关重要。Rendezvous 服务器 S 指示 A 和 B"同时"向彼此的地址发送数据包。为了实现这一点，S 可能指示 A 和 B 在一些初始延迟后向彼此发送数据包。此外，可能只有其中一个 NAT 会创建有效映射，而另一个收到意外响应。在这种情况下，应用可能需要使用不同端口重试该过程。

### 原文

##### 3.3.2. Peers behind the Same NAT

Consider the topology in figure 4. Two hosts, A and B, behind the same NAT wish to communicate. In this scenario, UDP hole punching can work if the NAT supports hairpinning.

### 中文

##### 3.3.2. 位于同一 NAT 后面的对等体

考虑图 4 中的拓扑。位于同一 NAT 后面的两个主机 A 和 B 希望通信。在这种情况下，如果 NAT 支持 hairpinning，UDP 打洞可以工作。

### 中文

A 和 B 各自向 rendezvous 服务器 S 发送 UDP 数据报。由于两个主机都在同一 NAT 上，NAT 为它们的私有端点分配公共端点。NAT A 将 A 的私有端点 10.0.0.1:1234 分配给公共端点 192.0.2.1:62000，B 也是如此（10.1.1.3:1234 分配给 192.0.2.1:62001）。然后 rendezvous 服务器 S 将每个主机对应的公共端点返回给对方。因此，A 得知 B 的公共端点是 192.0.2.1:62001，B 得知 A 的公共端点是 192.0.2.1:62000。

### 原文

Now A sends a UDP datagram to B's public endpoint (192.0.2.1:62001), and B sends a UDP datagram to A's public endpoint (192.0.2.1:62000) at roughly the same time. NAT A receives the datagram from A and forwards it to B's public endpoint (192.0.2.1:62001). The NAT examines the destination address, realizes it's an address for which it has a local mapping, and therefore "loops back" the packet to the internal host B. The same process happens on NAT B for the datagram from B to A.

### 中文

现在 A 向 B 的公共端点（192.0.2.1:62001）发送 UDP 数据报，B 同时向 A 的公共端点（192.0.2.1:62000）发送 UDP 数据报。NAT A 从 A 接收数据报并将其转发到 B 的公共端点（192.0.2.1:62001）。NAT 检查目标地址，意识到它是自己有本地映射的地址，因此将数据包"环回"到内部主机 B。同样的过程在 NAT B 上发生，用于从 B 到 A 的数据报。

---

### 原文

If the NAT does not support hairpinning, then the rendezvous server must perform the "help" function. The server S must relay all traffic between A and B. If the NAT does support hairpinning, but not EIM-NAT, then the hole punching technique may still work if both NATs have a predictable mapping behavior.

### 中文

如果 NAT 不支持 hairpinning，那么 rendezvous 服务器必须执行"帮助"功能。服务器 S 必须在 A 和 B 之间中继所有流量。如果 NAT 支持 hairpinning 但不是 EIM-NAT，那么如果两个 NAT 都具有可预测的映射行为，打洞技术可能仍然有效。

##### 3.3.3. Peers Separated by Multiple NATs

Consider the topology in figure 5. The two hosts, A and B, are separated by multiple NATs. In this scenario, which is common in wide-area preview deployments of Internet-connected hot spots, UDP hole punching can work if the NATs between the hosts are EIM-NATs.

##### 3.3.3. 被多个 NAT 分隔的对等体

考虑图 5 中的拓扑。两个主机 A 和 B 被多个 NAT 分隔。在这种场景中（这在互联网连接热点站点的广域网预览部署中很常见），如果主机之间的 NAT 是 EIM-NAT，UDP 打洞可以工作。

#### 3.4. TCP Hole Punching

TCP hole punching is analogous to UDP hole punching, but uses TCP instead of UDP. The process for establishing a direct TCP connection between two hosts behind NATs is similar to UDP hole punching.

### 中文

#### 3.4. TCP 打洞（TCP Hole Punching）

### 原文

#### 3.5. UDP Port Number Prediction

UDP port number prediction is a technique that exploits the predictable NAT behavior observed in some symmetric NATs. In this technique, the client guesses what NAT mapping will be created for its peer-to-peer connection.

### 中文

#### 3.5. UDP 端口号预测（UDP Port Number Prediction）

UDP 端口号预测是一种利用某些对称 NAT 可预测行为的技术。在这种技术中，客户端猜测将为其点对点连接创建什么 NAT 映射。

---

### 原文

The technique relies on the observation that some NATs, specifically symmetric NATs, assign ports on a sequential basis. For example, if an internal host sends a UDP datagram from port 1234 to an external IP address, the NAT may assign it an external port of 62000. If the same internal host sends another UDP datagram from the same internal port 1234 to a different external IP address, the NAT may assign the external port as 62001.

### 中文

该技术依赖于对某些 NAT（特别是对称 NAT）按顺序分配端口的观察。例如，如果内部主机从端口 1234 向外部 IP 地址发送 UDP 数据报，NAT 可能为其分配外部端口 62000。如果同一内部主机从同一内部端口 1234 向另一外部 IP 地址发送另一个 UDP 数据报，NAT 可能将外部端口分配为 62001。

---

### 原文

Given this predictable NAT behavior, the client can "guess" what port the NAT will assign for its peer-to-peer connection. The client probes the NAT to see what port is assigned when communicating with a given external host, and extrapolates to predict the port that would be assigned for communication with a different peer.

### 中文

根据这种可预测的 NAT 行为，客户端可以"猜测"NAT 将为其点对点连接分配什么端口。客户端探测 NAT 以查看与给定外部主机通信时分配了什么端口，并推断预测与不同对等体通信时会分配的端口。

---

### 原文

This technique is fragile because it assumes a particular NAT behavior that is often not observed in practice. Not all NATs assign ports sequentially, and the behavior may change from time to time. For these reasons, this technique is not considered reliable.

### 中文

该技术脆弱，因为它假设了一种在实践中经常观察不到的特殊 NAT 行为。并非所有 NAT 都按顺序分配端口，并且行为可能随时变化。由于这些原因，该技术被认为不可靠。

---

### 原文

#### 3.6. TCP Port Number Prediction

TCP port number prediction is analogous to UDP port number prediction, but uses TCP instead of UDP. The technique attempts to predict what ports a symmetric NAT will assign for a peer-to-peer connection based on past observations.

### 中文

#### 3.6. TCP 端口号预测（TCP Port Number Prediction）

### 原文

### 中文

该技术与其 UDP 对应物一样脆弱，不被认为是可靠的。对称 NAT 的行为可能不可预测，探测 NAT 可能产生不一致的结果。

## 4. Recent Work on NAT Traversal

### 原文

Since the publication of [STUN], there has been significant additional work on NAT traversal. [ICE] defines a mechanism that uses STUN and TURN to allow connections between peers, even when both peers are behind NATs. ICE works by exchanging multiple candidate addresses (including local, server-reflexive, and relayed addresses) and checking connectivity in a prioritized manner.

### 中文

自 [STUN] 发布以来，NAT 穿透方面已有大量额外工作。[ICE] 定义了一种机制，使用 STUN 和 TURN 允许对等体之间的连接，即使双方对等体都在 NAT 后面。ICE 通过交换多个候选地址（包括本地、服务器反射和中继地址）并以优先级方式检查连接来工作。

---

### 原文

[BEH-UDP] defines a standard for NAT behavior that is more amenable to peer-to-peer applications. The standard defines EIM-NAT, which greatly simplifies the NAT traversal problem. BEHAVE-compliant NATs are expected to become widely deployed.

### 中文

[BEH-UDP] 为更适合点对点应用的 NAT 行为定义了标准。该标准定义了 EIM-NAT，这大大简化了 NAT 穿透问题。预计符合 BEHAVE 的 NAT 将被广泛部署。

---

### 原文

[TURN] defines a mechanism for tunneling through NATs using a relay server. This is a fallback mechanism when direct communication cannot be established.

### 中文

[TURN] 定义了使用中继服务器通过 NAT 隧穿 的机制。这是在无法建立直接通信时的回退机制。

## 5. Summary of Observations

### 原文

Based on the techniques described above, we can make several observations about NAT traversal for P2P applications.

### 中文

基于上述技术，我们可以对 P2P 应用的 NAT 穿透做出若干观察。

---

### 原文

#### 5.1. TCP/UDP Hole Punching

UDP and TCP hole punching are the most efficient techniques for NAT traversal when they work. They require NATs to exhibit EIM behavior, which is becoming more common but not yet universal.

### 中文

#### 5.1. TCP/UDP 打洞

UDP 和 TCP 打洞是 NAT 穿透最有效的技术（当它们工作时）。它们要求 NAT 表现出 EIM 行为，这种行为越来越普遍但尚未普及。

---

### 原文

#### 5.2. NATs Employing Endpoint-Dependent Mapping

NATs that employ endpoint-dependent mapping (also known as symmetric NATs) are particularly problematic for P2P applications. Hole punching techniques do not work reliably with symmetric NATs, and relaying is often the only option.

### 中文

#### 5.2. 采用端点相关映射的 NAT

采用端点相关映射（也称为对称 NAT）的 NAT 对 P2P 应用特别成问题。打洞技术与对称 NAT 不能可靠地工作，中继通常是唯一的选择。

---

### 原文

#### 5.3. Peer Discovery

Peer discovery is a critical component of NAT traversal. A rendezvous server is typically used to exchange endpoint information between peers.

### 中文

#### 5.3. 对等发现

对等发现是 NAT 穿透的关键组件。Rendezvous 服务器通常用于在对等体之间交换端点信息。

---

### 原文

#### 5.4. Hairpinning

Hairpinning support in NATs is important for peers behind the same NAT to communicate directly. However, not all NATs support hairpinning.

### 中文

#### 5.4. Hairpinning

NAT 中的 hairpinning 支持对于位于同一 NAT 后面的对等体直接通信很重要。然而，并非所有 NAT 都支持 hairpinning。

## 6. Security Considerations

### 原文

The techniques described in this document have several security implications that applications should consider.

### 中文

本文档描述的技术有几个应用应考虑的安全影响。

---

### 原文

#### 6.1. Lack of Authentication Can Cause Connection Hijacking

Without proper authentication, a malicious host could potentially hijack a P2P connection by registering the same endpoint as a legitimate peer.

### 中文

#### 6.1. 缺乏身份验证可能导致连接劫持

如果没有适当的身份验证，恶意主机可能通过注册与合法对等体相同的端点来劫持 P2P 连接。

---

### 原文

#### 6.2. Denial-of-Service Attacks

NAT traversal techniques can be exploited for denial-of-service attacks. For example, an attacker could send a large number of connection requests to overwhelm a peer's NAT.

### 中文

#### 6.2. 拒绝服务攻击

NAT 穿透技术可能被利用进行拒绝服务攻击。例如，攻击者可以发送大量连接请求以压垮对等体的 NAT。

---

### 原文

#### 6.3. Man-in-the-Middle Attacks

Man-in-the-middle attacks are possible if an attacker can intercept and modify communications between peers during the connection establishment phase.

### 中文

#### 6.3. 中间人攻击

如果攻击者能够在连接建立阶段拦截和修改对等体之间的通信，则可能发生中间人攻击。

---

### 原文

#### 6.4. Security Impact from EIM-NAT Devices

EIM-NAT devices improve security by limiting the exposure of internal hosts to unsolicited traffic from the external network.

### 中文

#### 6.4. EIM-NAT 设备的安全影响

EIM-NAT 设备通过限制内部主机暴露于外部网络的未经请求的流量来提高安全性。
