# SIP: Session Initiation Protocol (RFC 3261)

## 一句话理解

**SIP = WebRTC 信令协议，用于建立/修改/终止多媒体会话（打电话）**

---

## 协议概述

### 什么是 SIP？

SIP (Session Initiation Protocol) 是**应用层控制协议**，用于：
- 创建会话
- 修改会话
- 终止会话

### SIP 的五大功能

| 功能 | 说明 |
|------|------|
| **用户定位** | 确定端系统位置 |
| **用户可用性** | 确定被叫方是否愿意通信 |
| **用户能力** | 确定媒体和媒体参数 |
| **会话建立** | 振铃、建立会话参数 |
| **会话管理** | 转移和终止会话、修改参数 |

### SIP 在架构中的位置

```
┌─────────────────────────────────────────────────────────────┐
│                  SIP 在 IETF 多媒体架构中的位置                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   SIP (信令控制) ── 与以下协议配合 ──                          │
│      │                                                      │
│      ├── RTP (RFC 1889) ─ 实时传输音视频                      │
│      ├── RTSP (RFC 2326) ─ 流媒体控制                        │
│      ├── MEGACO ─ 网关控制 (PSTN)                            │
│      └── SDP (RFC 2327) ─ 描述多媒体会话                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## SIP URI

### 什么是 SIP URI？

SIP URI 是用户的标识，格式类似 email 地址：

```
sip:用户名@域名
sips:用户名@域名 (安全版本，使用 TLS)
```

### 示例

| URI | 说明 |
|-----|------|
| `sip:bob@biloxi.com` | Bob 的 SIP 地址 |
| `sip:alice@atlanta.com` | Alice 的 SIP 地址 |
| `sips:bob@biloxi.com` | 安全的 Bob 地址 |

### SIP URI vs SIPS URI

| 类型 | 安全性 | 说明 |
|------|--------|------|
| `sip:` | 明文 | 不保证加密 |
| `sips:` | TLS 加密 | 端到端加密传输 |

## SIP 消息结构

### 消息格式

```
┌─────────────────────────────────────────────────────────────┐
│  SIP 消息格式                                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  请求消息:                                                   │
│    METHOD sip:user@domain SIP/2.0                           │
│    Header1: value                                           │
│    Header2: value                                           │
│                                                             │
│    [Body: SDP 等]                                           │
│                                                             │
│  响应消息:                                                   │
│    SIP/2.0 200 OK                                           │
│    Header1: value                                           │
│    Header2: value                                           │
│                                                             │
│    [Body: SDP 等]                                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 请求消息示例 (INVITE)

```
INVITE sip:bob@biloxi.com SIP/2.0
Via: SIP/2.0/UDP pc33.atlanta.com;branch=z9hG4bK776
Max-Forwards: 70
To: Bob <sip:bob@biloxi.com>
From: Alice <sip:alice@atlanta.com>;tag=1928301774
Call-ID: a84b4c76e66710@pc33.atlanta.com
CSeq: 314159 INVITE
Contact: <sip:alice@pc33.atlanta.com>
Content-Type: application/sdp
Content-Length: 147

v=0
o=alice 53655765 2353687637 IN IP4 pc33.atlanta.com
...
```

### 响应消息示例 (200 OK)

```
SIP/2.0 200 OK
Via: SIP/2.0/UDP pc33.atlanta.com;branch=z9hG4bK776
To: Bob <sip:bob@biloxi.com>;tag=a6c85cf
From: Alice <sip:alice@atlanta.com>;tag=1928301774
Call-ID: a84b4c76e66710@pc33.atlanta.com
CSeq: 314159 INVITE
Contact: <sip:bob@pc55.biloxi.com>
Content-Type: application/sdp
Content-Length: 147

v=0
o=bob 53655763 2353687638 IN IP4 pc55.biloxi.com
...
```

## SIP 方法 (Methods)

### 主要方法

| 方法 | 英文 | 用途 |
|------|------|------|
| **INVITE** | Invite | 发起会话邀请 |
| **ACK** | Acknowledgement | 确认最终响应 |
| **BYE** | Bye | 终止会话 |
| **CANCEL** | Cancel | 取消正在进行的请求 |
| **REGISTER** | Register | 注册用户位置 |
| **OPTIONS** | Options | 查询能力 |

### INVITE 方法详解

**INVITE** 用于发起会话建立请求：

```
┌─────────────────────────────────────────────────────────────┐
│  INVITE 消息流程                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Alice ──INVITE──▶ Proxy ──INVITE──▶ Bob                    │
│                  ◀──100 Trying──                            │
│                                    ◀──180 Ringing──         │
│                                    ◀──200 OK ──────────     │
│                  ◀──200 OK ──────────────────────────       │
│  Alice ──ACK───────────────────────────────────────────▶    │
│                                    ◀──媒体流───────────▶     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### REGISTER 方法详解

**REGISTER** 用于用户注册位置：

```
┌─────────────────────────────────────────────────────────────┐
│  REGISTER 位置注册                                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  User Agent ──REGISTER──▶ Registrar                         │
│               ◀──200 OK ─────────────────────────────────   │
│                                                             │
│  绑定关系: SIP URI ↔ Contact (当前地址)                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## SIP 响应码

### 1xx - Provisional ( provisional 临时响应)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **100** | Trying | 正在尝试处理 |
| **180** | Ringing | 对方正在响铃 |
| **181** | Call Is Being Forwarded | 呼叫正在转移 |
| **182** | Queued | 呼叫排队中 |
| **183** | Session Progress | 会话进展中 |

### 2xx - Successful (成功响应)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **200** | OK | 请求成功 |

### 3xx - Redirection (重定向)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **300** | Multiple Choices | 多个选择 |
| **301** | Moved Permanently | 永久移动 |
| **302** | Moved Temporarily | 临时移动 |
| **305** | Use Proxy | 使用代理 |
| **380** | Alternative Service | 替代服务 |

### 4xx - Request Failure (请求失败)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **400** | Bad Request | 错误请求 |
| **401** | Unauthorized | 未授权 |
| **403** | Forbidden | 禁止访问 |
| **404** | Not Found | 未找到 |
| **405** | Method Not Allowed | 方法不允许 |
| **407** | Proxy Authentication Required | 需要代理认证 |
| **408** | Request Timeout | 请求超时 |
| **415** | Unsupported Media Type | 不支持的媒体类型 |
| **480** | Temporarily Unavailable | 临时不可用 |
| **486** | Busy Here | 忙 |

### 5xx - Server Failure (服务器失败)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **500** | Server Internal Error | 服务器内部错误 |
| **503** | Service Unavailable | 服务不可用 |
| **504** | Server Time-out | 服务器超时 |

### 6xx - Global Failures (全局失败)

| 状态码 | 含义 | 说明 |
|--------|------|------|
| **600** | Busy Everywhere | 到处都忙 |
| **603** | Decline | 拒绝 |
| **604** | Does Not Exist Anywhere | 不存在任何地方 |
| **606** | Not Acceptable | 不可接受 |

## 核心 Header 字段

### From / To / Contact

| 字段 | 说明 | 示例 |
|------|------|------|
| **From** | 发送方 | `From: <sip:alice@atlanta.com>;tag=1928301774` |
| **To** | 接收方 | `To: Bob <sip:bob@biloxi.com>` |
| **Contact** | 直接联系地址 | `Contact: <sip:alice@pc33.atlanta.com>` |

### Call-ID / CSeq

| 字段 | 说明 | 示例 |
|------|------|------|
| **Call-ID** | 唯一标识会话 | `Call-ID: a84b4c76e66710@pc33.atlanta.com` |
| **CSeq** | 命令序列号 | `CSeq: 314159 INVITE` |

### Via / Route / Record-Route

| 字段 | 说明 | 用途 |
|------|------|------|
| **Via** | 路由追踪 | 记录请求经过的路径 |
| **Route** | 强制路由 | 强制请求经过指定代理 |
| **Record-Route** | 记录路由 | 要求后续请求经过代理 |

## SIP 核心概念

### User Agent (用户代理)

```
┌─────────────────────────────────────────────────────────────┐
│  User Agent (UA)                                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────┐    ┌───────────────┐                     │
│  │   User Agent  │    │   User Agent  │                     │
│  │   Client      │    │   Server      │                     │
│  │   (UAC)       │◀──▶│   (UAS)       │                     │
│  └───────────────┘    └───────────────┘                     │
│                                                             │
│  UAC = 发起请求的 UA                                         │
│  UAS = 接收请求的 UA                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Proxy Server (代理服务器)

**代理服务器** 转发 SIP 请求：

| 类型 | 说明 |
|------|------|
| **Stateful Proxy** | 维护事务状态，可靠转发 |
| **Stateless Proxy** | 仅转发，不维护状态 |

### Registrar (注册服务器)

**注册服务器** 处理 REGISTER 请求，存储用户位置绑定：

```
┌─────────────────────────────────────────────────────────────┐
│  注册流程                                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. User Agent ──REGISTER──▶ Registrar                      │
│                     (含 Contact 地址)                        │
│                                                             │
│  2. Registrar 保存绑定:                                      │
│     sip:alice@atlanta.com → sip:alice@pc33.atlanta.com      │
│                                                             │
│  3. Proxy 根据绑定转发后续请求                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## SIP 事务 (Transaction)

### INVITE 事务

```
┌─────────────────────────────────────────────────────────────┐
│  INVITE 事务 (三次握手)                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Client ──INVITE──▶ Server                                  │
│  Client ◀──1xx ────────────────────────────────────         │
│  Client ◀──2xx ────────────────────────────────────         │
│  Client ──ACK───────────────────────────────────▶           │
│                                                             │
│  特点: INVITE 事务以 2xx 或 ACK 结束                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Non-INVITE 事务

```
┌─────────────────────────────────────────────────────────────┐
│  Non-INVITE 事务 (请求-响应)                                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Client ──BYE/CANCEL/OPTIONS──▶ Server                      │
│  Client ◀──Response ─────────────────────────               │
│                                                             │
│  特点: 请求-响应模式                                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## Dialog (对话)

### 什么是对话？

**Dialog** = 两个 UA 之间持续一定时间的对话关系

### Dialog 建立条件

| 方向 | From Tag | To Tag | Call-ID |
|------|---------|--------|---------|
| **UAC** | ✅ | ✅ | ✅ |
| **UAS** | ✅ | ✅ | ✅ |

### 对话内请求

对话建立后，后续请求使用相同的 Call-ID 和 Tags：

```
┌─────────────────────────────────────────────────────────────┐
│  对话内请求                                                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  INVITE ───────────────▶  │ 建立 Dialog                      │
│  200 OK ◀──────────────   │                                 │
│  ACK ──────────────────▶  │                                 │
│                           │                                 │
│  BYE ───────────────────▶ │ 在同一 Dialog 中                  │
│  200 OK ◀──────────────   │                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## WebRTC 中的 SIP

### SIP 与 WebRTC 的关系

```
┌─────────────────────────────────────────────────────────────┐
│  WebRTC 信令层                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────────────────────────────────────┐        │
│  │  SDP (Session Description Protocol)             │        │
│  │  - 描述媒体能力 (codec, bandwidth)                │        │
│  │  - 描述网络信息 (ICE candidates)                  │        │
│  │  - 通过 SIP/SDP Offer-Answer 交换                │        │
│  └─────────────────────────────────────────────────┘        │
│                                                             │
│  ┌─────────────────────────────────────────────────┐        │
│  │  SIP (Session Initiation Protocol)              │        │
│  │  - 建立/修改/终止会话                             │        │
│  │  - 携带 SDP 作为消息体                            │        │
│  │  - 交换 ICE candidates                           │        │
│  └─────────────────────────────────────────────────┘        │
│                                                             │
│  ┌─────────────────────────────────────────────────┐        │
│  │  ICE (Interactive Connectivity Establishment)   │        │
│  │  - 候选收集                                      │        │
│  │  - 连接性检查                                     │        │
│  │  - 提名 Selected Pair                            │        │
│  └─────────────────────────────────────────────────┘        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### WebRTC 信令流程

```
┌─────────────────────────────────────────────────────────────┐
│  WebRTC 信令流程                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Peer A                              Peer B                 │
│    │                                    │                   │
│    │ 1. 创建 Offer (SDP)                 │                   │
│    │───INVITE + SDP───────────────────▶ │                   │
│    │                                    │                   │
│    │ 2. ICE 候选交换                     │                   │
│    │◀───ICE candidates───────────────▶  │                   │
│    │                                    │                   │
│    │ 3. 创建 Answer (SDP)                │                   │
│    │◀──200 OK + SDP──────────────────── │                   │
│    │                                    │                   │
│    │ 4. ICE 连接性检查                   │                   │
│    │◀═══════════════════════════════▶   │                   │
│    │                                    │                   │
│    │ 5. RTP 媒体传输                     │                   │
│    │◀═══════════════════════════════▶   │                   │
│    │                                    │                   │
│    │ 6. 结束会话                         │                   │
│    │───BYE───────────────────────────▶  │                   │
│    │◀──200 OK─────────────────────────  │                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 与 WebRTC 其他协议的关系

| 协议 | RFC | 作用 |
|------|------|------|
| **SIP** | RFC 3261 | 信令控制 (建立/终止会话) |
| **SDP** | RFC 4566 | 会话描述 (媒体参数) |
| **ICE** | RFC 8445 | NAT 穿透 (候选收集/检查) |
| **STUN** | RFC 5389 | NAT 穿透 (发现公网地址) |
| **TURN** | RFC 5766 | NAT 穿透 (中继) |
| **RTP** | RFC 3550 | 音视频传输 |
| **RTP A/V Profile** | RFC 3551 | 负载类型映射 |
| **DTLS** | RFC 6347 | 加密传输 |

---

## 一句话总结

> **SIP = WebRTC 的信令协议，负责建立/修改/终止会话**
>
> **INVITE = 建立会话，BYE = 终止会话，REGISTER = 注册位置**
>
> **SIP URI = 用户的标识，类似 email 地址**
>
> **Proxy = 转发请求，Registrar = 存储位置绑定**
