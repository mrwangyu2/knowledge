# RTP Profile for Audio and Video Conferences (RFC 3551)

## 一句话理解

**RFC 3551 (RTP/AVP) = 为 RTP 定义了音视频编码与负载类型 (Payload Type) 的标准映射表**

---

## 协议概述

### 什么是 RTP/AVP Profile？

**RTP/AVP** (Audio Video Profile) 是 RFC 3550 (RTP) 的一个子规范，定义：

| 方面 | 说明 |
|------|------|
| **适用范围** | 多方音视频会议，最小会话控制 |
| **核心内容** | 负载类型编号 → 编码格式的静态映射表 |
| **不提供** | 参数协商、成员控制 (由上层协议如 SDP 提供) |
| **RTP 标记位** | 使用 1 个标准标记位 (M bit) |

### Profile 的关键约定

| 约定             | 值                          |
| -------------- | -------------------------- |
| **RTCP 带宽**    | 发送方 1.25%，接收方 3.75%（合计 5%） |
| **CNAME 发送频率** | 每个报告间隔必须发送                 |
| **其他 SDES 项**  | 每 3 个间隔发送一次                |
| **默认注册端口**     | RTP=5004, RTCP=5005        |
|                |                            |

## 负载类型 (Payload Type) 总览

### 核心概念

```
┌─────────────────────────────────────────────────────────────┐
│  Payload Type 分类                                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  PT 0-34      静态映射 (已固定，不再新增)                       │
│  │  └─ 音频: 0-23 (部分 reserved/unassigned)                 │
│  │  └─ 视频: 24-34                                           │
│  │                                                          │
│  PT 35-71     unassigned (未分配)                            │
│  PT 72-76     保留 (区分 RTP/RTCP)                           │
│  PT 77-95     unassigned (未分配)                            │
│  PT 96-127    动态分配 (通过 SDP/H.245 协商)                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

| 帧率 | 每帧 TS 增量 |
|------|-------------|
| 24 fps (HDTV) | 3750 |
| 25 fps (PAL) | 3600 |
| 29.97 fps (NTSC) | ≈3003 |
| 30 fps (HDTV) | 3000 |

## 编码分类与规则

### 基于采样 (Sample-Based) vs 基于帧 (Frame-Based)

```
┌─────────────────────────────────────────────────────────────┐
│  编码分类                                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  基于采样 (Sample-Based)                                     │
│  ├─ 每个样本固定比特数                                         │
│  ├─ 样本可跨越字节边界                                         │
│  ├─ 多字节用大端序                                            │
│  └─ 代表: PCMU, PCMA, L16, DVI4, G726, G722                  │
│                                                             │
│  基于帧 (Frame-Based)                                        │
│  ├─ 每帧是独立编码块                                           │
│  ├─ 一帧可有多个字节                                           │
│  ├─ 可在一包中组合多帧                                         │
│  └─ 代表: GSM, G723, G728, G729, H264                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 通用规则

| 规则 | 说明 |
|------|------|
| **静音抑制** | 允许断续传输，首包设置 M=1 |
| **舒适噪音** | CN 负载格式 (RFC 3389)，用不同 PT 值区分 |
| **默认打包间隔** | 20ms 或 1 帧，取较大值 |
| **接收方容错** | 接受 0-200ms 的音频数据 |
| **时间戳** | 反映第一个采样/帧的采样时刻 |

### 视频通用规则

| 规则 | 说明 |
|------|------|
| **时间戳** | 推荐 90,000 Hz |
| **多包一帧** | 同一帧的所有包时间戳相同 |
| **标记位** | 帧的最后一个包 M=1，其余 M=0 (便于无需等待下帧即可检测帧边界) |

### 声道顺序

```
┌─────────────────────────────────────────────────────────────┐
│  声道布局（遵循 AIFF-C 约定）                                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  2 声道 (立体声):    L(1)  R(2)                               │
│  3 声道:             L(1)  R(2)  C(3)                        │
│  4 声道:             L(1)  C(2)  R(3)  S(4)                  │
│  5 声道:            Fl(1) Fr(2) Fc(3) Sl(4) Sr(5)            │
│  6 声道:             L(1) Lc(2)  C(3)  R(4) Rc(5)  S(6)      │
│                                                             │
│  规则:                                                       │
│  - 同一采样时刻的所有声道样本必须在同一包中                       │
│  - 低声道号数据在前，高声在后                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## WebRTC 中的 RTP/AVP

### WebRTC 使用的编码

WebRTC **不使用** RFC 3551 的静态映射表，而是通过 SDP 动态协商编码：

| 类型 | WebRTC 常用编码 | PT | RFC 3551 对应 |
|------|----------------|----|--------------|
| **音频** | Opus | 动态 (96-127) | — (核心音频编码) |
| **音频** | G.711 PCMU | 0 | ✅ PT=0 |
| **音频** | G.711 PCMA | 8 | ✅ PT=8 |
| **音频** | G.722 | 9 | ✅ PT=9 |
| **音频冗余** | RED | 动态 | ✅ dyn |
| **舒适噪音** | CN | 13 | ✅ PT=13 |
| **视频** | VP8 | 动态 | — |
| **视频** | VP9 | 动态 | — |
| **视频** | H.264/AVC | 动态 | — |
| **视频** | H.265/HEVC | 动态 | — |
| **视频** | AV1 | 动态 | — |

> WebRTC 保留了 PT 0 (PCMU) 和 PT 8 (PCMA) 的静态映射以兼容传统电话系统，但核心音频编码 Opus 总是动态分配。

## 与 WebRTC 其他协议的关系

| 协议                  | RFC      | 作用            | 关系                 |
| ------------------- | -------- | ------------- | ------------------ |
| **RTP**             | RFC 3550 | 实时传输协议        | RTP/AVP 是其 Profile |
| **RTP A/V Profile** | RFC 3551 | 定义 PT↔编码映射    | 本文档                |
| **SDP**             | RFC 4566 | 会话描述          | 动态 PT 通过 SDP 协商    |
| **SRTP**            | RFC 3711 | RTP 加密        | 保护 RTP/AVP 负载      |
| **Opus**            | RFC 6716 | WebRTC 核心音频编码 | 动态 PT 分配           |
| **RED**             | RFC 2198 | 冗余音频          | 提高丢包容错             |

## 一句话总结

> **RTP/AVP = RFC 3550 的子规范，定义 PT 编号到编码格式的映射表**
>
> **静态 PT 0-34 (0=PCMU, 8=PCMA, 9=G722...)，动态 PT 96-127**
>
> **视频统一 90kHz 时钟，音频时钟由编码决定** 
>
> **WebRTC 继承 PT 0/8 兼容 PSTN，核心编码 Opus/VP8/H264 均动态分配**
>
> **默认 20ms 打包间隔，M 位标记帧边界**
